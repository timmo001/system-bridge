Download the package for your platform from the [releases page](https://github.com/timmo001/system-bridge/releases).

Each release ships these assets:

- Arch Linux: `system-bridge-*-x86_64.pkg.tar.zst` (stable releases only)
- Debian / Ubuntu: `system-bridge_<version>_<arch>.deb`
- Fedora / RHEL: `system-bridge-<version>.<arch>.rpm`
- Flatpak: `system-bridge-<version>.flatpak`
- Windows: `system-bridge-<version>-setup.exe`

:::note
Stable builds are attached to the releases page. Development builds from the latest `dev` branch are also available as workflow artifacts on the [GitHub Actions runs](https://github.com/timmo001/system-bridge/actions), which require a GitHub account to download.
:::

<Tabs syncKey="os">
<Tab title="Linux">

Install the package that matches your distribution's package manager.

<Tabs syncKey="distro">
<Tab title="Arch Linux">

Install from the AUR with an AUR helper such as [yay](https://github.com/Jguer/yay).

For the latest stable release, use the [system-bridge](https://aur.archlinux.org/packages/system-bridge) package:

```bash
yay -S system-bridge
```

For the development branch, use the [system-bridge-git](https://aur.archlinux.org/packages/system-bridge-git) package. This builds and installs the application from the latest `dev` branch, which is updated automatically every commit:

```bash
yay -S system-bridge-git
```

Alternatively, install the `.pkg.tar.zst` from the releases page or downloaded workflow asset directly:

```bash
sudo pacman -U system-bridge-*-x86_64.pkg.tar.zst
```

</Tab>
<Tab title="Debian / Ubuntu">

Install the `.deb` asset with `apt` so dependencies are resolved automatically:

```bash
sudo apt install ./system-bridge_<version>_<arch>.deb
```

You can also install it with `dpkg`:

```bash
sudo dpkg -i system-bridge_<version>_<arch>.deb
```

</Tab>
<Tab title="Fedora / RHEL">

Install the `.rpm` asset with `dnf`:

```bash
sudo dnf install ./system-bridge-<version>.<arch>.rpm
```

</Tab>
<Tab title="Flatpak">

Install the `.flatpak` bundle:

```bash
flatpak install system-bridge-<version>.flatpak
```

Then run it with:

```bash
flatpak run dev.timmo.system-bridge
```

</Tab>
</Tabs>

</Tab>
<Tab title="Windows">

Run the `system-bridge-<version>-setup.exe` installer to install the application. After installation completes, you can start System Bridge from the Start Menu shortcut.

</Tab>

## Updating

On Linux, System Bridge restarts itself within a minute of a package update replacing it, so the new version runs without you restarting it. Flatpak keeps running the version it started with, so restart System Bridge after updating it there.

## Optional dependencies

System Bridge reads most hardware metrics directly from the kernel, so these tools aren't required. On Linux, installing them improves detection on some systems:

| Package | Tool | What it adds |
| --- | --- | --- |
| `lm_sensors` (Arch, Fedora), `lm-sensors` (Debian / Ubuntu) | `sensors` | The full set of temperature and fan sensors on some boards. Run `sudo sensors-detect` once to load the relevant modules. |
| `nvidia-utils` | `nvidia-smi` | NVIDIA GPU metrics. Intel and AMD GPUs use the kernel `drm`/`hwmon` interfaces and need nothing extra. |
| `pciutils` | `lspci` | Friendly GPU model names. GPUs are still detected without it, but fall back to a generic name. |
| `pipewire` (Arch), `pipewire-bin` (Debian / Ubuntu), `pipewire-utils` (Fedora) | `pw-dump` | Names the apps using the microphone or camera. Without it, microphone usage falls back to ALSA, which names the sound server instead of the app. |
| `zenity` | `zenity` | The confirmation before **Quit** or **Hide system tray**. Without it, those actions can't be confirmed, so they don't run. |
| `libpulse` (Arch), `pulseaudio-utils` (Debian / Ubuntu, Fedora) | `pactl`, `paplay` | Audio devices and [audio controls](/features/remote-control/#audio), and notification sounds. Needs PulseAudio 16 or later, or PipeWire with `pipewire-pulse`. |
| `alsa-utils` | `aplay` | Notification sounds when `paplay` isn't installed. |
| `bluez` | `bluetoothd` | Bluetooth devices and [Bluetooth controls](/features/remote-control/#bluetooth). |
| `ddcutil` | `ddcutil` | Brightness and power for [external monitors](/features/remote-control/#displays) over DDC/CI. Needs access to `/dev/i2c-*`, usually by being in the `i2c` group. |

The `.deb` and `.rpm` packages recommend `pciutils`, PipeWire, `zenity` and `pulseaudio-utils`, so `apt` and `dnf` install them by default. The Arch package lists all of these as optional dependencies, which `pacman` shows but doesn't install.

The [command prefabs](/features/commands/#prefab-commands) run tools for the desktop you're on, such as `wl-clipboard` for the clipboard or `grim` for screenshots. A prefab that can't run says which tools it looks for. [Setting the clipboard](/features/remote-control/#clipboard) uses the same clipboard tools.

On Windows, the waiting package update count needs [winget](https://learn.microsoft.com/windows/package-manager/winget/), which Windows 11 includes. Nothing else is needed.
